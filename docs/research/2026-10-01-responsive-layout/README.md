# TAPtoTEST — 기기 비율에 맞는 반응형 화면

## 문제와 결정

설치 앱을 테스트한 사용자가 긴 휴대폰과 태블릿에서 커버·메인 화면의 가장자리와 간격이 다르게 보이는 문제를 제보했다. 기존 1.0.4/code6는 화면 확대 설정의 영향을 없애기 위해 390×844 화면 전체를 균일 배율로 맞추었다. 이 방식은 기기 비율까지 고정하므로 긴 창에서는 위아래, 넓은 창에서는 양옆에 남는 공간이 생긴다. 로컬 모의 화면에서도 이 남는 영역을 확인했다. 실제 설치 기기의 크롭 상태까지 이번 모의검사로 증명한 것은 아니다.

사용자는 다음 방식으로 정했다. 커버는 처음에는 화면 채우기를 허용했으나 후속 요청에서 가로폭 맞춤으로 변경했다.

- 스튜디오: 원래 `#fccf00` 배경을 채우고 로고 글씨까지 온전히 표시한다.
- 커버: 원본 이미지 **한 장을 가로폭에 맞추고 비율을 유지해 세로 중앙에 배치**한다. 좌우를 자르지 않고 위아래의 기존 그라데이션을 흰 배경에 이어지게 한다. 배경만 이어 붙이거나 새로 만들지 않는다.
- 메인부터: 흰 배경을 채우고 실제 기기 비율에 맞춰 콘텐츠를 배치한다. OS 화면 확대 설정에 따라 같은 기기의 배치가 변하지 않게 한다. 게임 내 배율 조절 메뉴는 추가하지 않는다.

## 구현

`src/ui/nativeFrame.ts`의 기준 너비 390은 유지하되 높이 844는 고정값이 아니라 참조로 사용한다. 가용 너비/390과 가용 높이/640 중 작은 값으로 균일 배율을 계산하고, 나머지 논리 너비·높이는 실제 창 비율에 따라 늘어난다. 같은 물리 화면에서 OS density만 바뀌면 논리 치수는 유지되고 물리 배율도 상쇄된다. OS 설정 자체는 변경하지 않는다.

스튜디오·커버의 배경만 실제 WebView 창 전체를 칠한다. 커버 이미지는 `width:100%; height:auto; top:50%; transform:translateY(-50%); object-fit:contain`으로 가로폭에 맞춘다. 원본 파일과 그라데이션은 수정하지 않았다. 긴 화면에서는 이미지 위아래의 흰색으로 사라지는 부분이 화면의 흰 배경에 이어진다. 좌우는 전부 보이며, 이미지보다 짧은 화면에서는 위아래만 중앙 기준으로 잘린다. 별도 CSS 그라데이션·합성·반복 배경은 만들지 않는다. WebView 밖의 네이티브 영역까지 HTML이 직접 칠한다는 의미도 아니다.

`src/ui/styles/nativeResponsive.css`에서 Android의 제시 그림 크기·간격을 가용 높이에 맞추고, 넓은 창에서는 HUD·그림·보드를 중앙에 모은다. `pickLayout.ts`는 실제 남은 공간을 측정해 정사각형 보드가 들어가게 제한한다. 계산 시 정수로 반올림된 `offsetHeight` 대신 소수점 계산 높이를 사용해 density에 따른 미세한 크기 차이를 막는다. 설정의 정책 안내창은 app 밖에 있으므로 원래 viewport 단위의 native inset으로 안전영역을 적용한다.

게임 규칙, 단계, 타이머, 이미지, 폰트, 기존 강조색과 효과, 음악, 기록 저장 형식, Android 패키지·서명 키·버전은 변경하지 않았다. 메인·게임의 웹 배치도 기존대로 유지한다. 웹 커버에도 같은 가로폭 맞춤이 적용된다. TAPtoTALK·TAPtoTEN 저장소는 수정하지 않았다.

## 전후 화면

[비교 페이지 열기](index.html)에서 비율과 화면을 선택할 수 있다. 캡처는 리사이즈하지 않은 PNG이며 다음 세 가지 실제 파일 해상도로 저장했다.

| 캡처 비율 | PNG 해상도 | 확인 대상 |
| --- | --- | --- |
| 기준 모바일 | 780×1688 | 로고·커버·메인·START·세 게임·일시정지·결과·설정 |
| 긴 휴대폰 | 1080×2700 | 같은 화면의 세로 공간 배치와 커버 좌우 전체 표시·위아래 흰 배경 연결 |
| 4:3 태블릿 | 1728×2304 | 같은 화면의 중앙 배치와 커버 위아래 크롭 |

커버 비교는 `cover-width/before/`의 화면 채우기 버전과 `cover-width/after/`의 가로폭 맞춤 버전이다. 최초 반응형 검증은 `final/before/`, `final/after/`에 보존했다. 이 폴더의 수정 전은 `ff1594a` / 1.0.4/code6, 수정 후는 커버 후속 변경 전의 반응형 빌드다. 비교 페이지는 커버를 선택하면 최신 가로폭 맞춤 이미지를 표시한다. 메인·게임·스튜디오는 후속 커버 변경으로 달라지지 않았다. PORTRAIT 3×3·4×4·5×5·문 교환, POSITION 4×4·6×6·완주 결과도 저장했다. 이 단계들의 수정 전 캡처는 없어 비교 페이지에서 명시한다.

캡처는 Chrome의 Android 플랫폼·시스템 바 겹침 **모의 환경**이다. 실제 갤럭시/태블릿 설치 앱 캡처, 시스템 바 외관, 네이티브 저장소, 업데이트 데이터 유지 검증을 대신하지 않는다. 테스트 설정은 `tests/browser/native-responsive.cjs`에 있다.

## 검증

- `npm test`: 35개 파일, 354개 테스트 통과.
- `npm run build`: TypeScript·Vite 빌드 통과.
- [커버 가로폭 후속 검증](cover-width/verification.json): 같은 7종 창에서 52개 로고·커버 검사, 6개 동일 기기 density 비교를 통과했다. 가로폭 일치·원본 비율·세로 중앙 배치를 확인하고 비교 PNG 12개를 추가했다. JS 오류 0개. 실제 설치 앱 검증은 아니다.
- [최초 기기 비율·density 검증](final/verification.json): 커버 후속 변경 전 모바일 4종·세로 태블릿 2종·넓은 창 1종, 329개 화면 검사·42개 동일 기기 density 비교·81개 PNG. JS 오류 0개. 변경하지 않은 메인·게임 배치 검증을 포함한다.
- [실행 중 변경·웹 회귀 검증](regression/verification.json): density 2/2.4/3/3.6/4, 110개 검사·12개 PNG. 같은 실행 중 확대/안전영역 변경과 원본 9/12조각, 실제 터치·완주 결과를 검사했다. 명시적 native inset 0도 유지했다.
- 웹 390×844·360×780·320×650·390×700·390×701에서 기존 메인·퍼즐의 위치·크기·서체 비교 통과.
- PORTRAIT 4/9/16/25칸과 문 교환, POSITION 4/16/36칸, PUZZLE 49칸의 정사각형 보드·안전영역·그림 간 겹침 없음 확인.

`nativeDeviceTested: false`다. 실제 Android WebView에서 화면 확대 설정 변경·상태/내비게이션 바·태블릿 비율은 새 빌드 설치 후 추가 확인해야 한다.

## 배포 상태

**소스 수정·검증까지만 수행했다. AAB 생성, Capacitor sync, commit, push, Play 업로드는 하지 않았다.** 기존 1.0.4/code6 AAB와 앱에 이번 수정이 자동으로 들어가지 않는다. 사용자의 다음 배포 요청 때 같은 패키지·기존 키를 유지하고 versionCode를 올려 새 파일을 생성한다.

이 연구기록은 게임에서 불러오지 않는다. 기존 AAB·이전 연구기록·별도 `presentation/` 파일은 유지했다.
